About

A directory that shows its work.

German Unicorns is a public register of Germany's currently private companies valued at a billion euros or more, built so that every figure on it can be checked against a public, dated source rather than taken on trust.

Why this exists

Germany is one of Europe's largest technology markets, and Europe's own venture and scale-up capital has become a live policy question in its own right. That debate deserves a factual, checkable baseline rather than a round number repeated without its source. This site exists to provide that baseline for one country: every company listed is verified against a public announcement, every valuation carries the date it was true, and every claim is open to correction — open any company's entry to see its own figures next to the sources behind them.

What gets listed

Three tests, and a company has to pass all three: it was founded in Germany or is headquartered here; it is still independent and still private — not listed, not acquired, not insolvent; and it has been publicly reported to be worth at least a billion dollars or a billion euros, in whichever currency the source used. Companies that fail one of those are listed too, in the candidates file, with the reason and its source — an exclusion is a finding, not an omission.

Membership is the test; the exact figure is a nice-to-have. Some companies everybody agrees are unicorns have never had a number published about them: the trade press reports that they passed a billion and prints no figure, and the company says nothing. Those entries show Undisclosed in place of a valuation, with a marker showing they are over the threshold and the sentence that establishes it, linked to the page it came from. That is deliberate. The alternative — inferring a figure nobody published, or dropping a real unicorn over how a sentence happened to be phrased — would make this register less true, not more precise. Those companies are also left out of the "combined value" total on the front page rather than counted as zero, and that total says how many of the register it covers.

Free and open

The site costs nothing to run and nothing to read. There is no paywall, no account, and no advertising. The code and the entire dataset — one JSON file per company — are public on GitHub at github.com/LW7776/Unicorn-Germany, where every past change is visible as a diff against the file it edited. Nothing here relies on a paid API or a licensed data feed.

How it's built

Each company is one JSON file, and nothing about it reaches the live site unless a Python validator confirms every figure in it carries a dated, quoted source — the same check runs on every proposed change, with no exception and no separate publish path. The site itself is static HTML, CSS and JavaScript: no build step, no framework, no database, served at no cost by GitHub Pages. The one standing automation is a GitHub Action that reads trade-press feeds once a month and opens an issue listing what it finds. It never edits company data itself; turning a candidate into a real update is a separate, human-reviewed step.

How updating works

An automated scan runs monthly and can also be triggered on demand. It reads the RSS feeds of the allowlisted trade press, matches articles against tracked company names and trigger words — raises, Series, valuation, unicorn, IPO, insolvency — and flags candidates: companies not yet tracked whose headline reports a valuation at or above $1B or €1B, or existing companies with a new figure to record. The scan does not check nationality — that is for the person reviewing the issue to confirm, the same as everything else it flags. The scan opens a GitHub issue listing what it found, with the headline, publication and link for each candidate.

Nothing is published from that issue automatically. A person reads the flagged articles, proposes the JSON edit with its source quote attached, and the site's validation checks run against it before it can be merged. Every update — automated candidate or manual correction — lands as a pull request and a reviewable diff, with a human as the approval gate.

Every record can also be changed by hand, three ways: GitHub's own web editor (linked from the bottom of each company's detail window), a local form editor that mirrors the same validation rules as you type, or editing the files directly. All three end in the same place — a commit that is validated before it can publish, so a bad hand edit can never break the live site. See docs/UPDATING.md for the exact steps.

Corrections

If something here is wrong, out of date, or missing a source, open an issue on the GitHub issue tracker, or use the "Report an error" link in the footer of any page.
